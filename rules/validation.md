# Rule Module — Validation

## Purpose

Audit generated pack before delivery. Repair if needed.

## Checklist

### A. Page Budget

- Estimated pages ≤ budget
- Estimate: ~500 words/page prose, ~700 tables/code

### B. Coverage

- Every in-scope topic has a section
- Required formulas present
- Required definitions present

### C. Source Grounding

- Every nontrivial claim tagged
- `[general]` tags rare and justified
- No fabricated facts

### D. Duplication

- No concept twice without cross-reference
- Cross-refs use correct section numbers

### E. Navigation

- TOC present and accurate
- Quick revision sheet present
- Index present
- Section numbering consistent

### F. Formatting

- Formulas visually distinct
- Code blocks have language tags
- Tables well-formed
- Headings consistent

### G. Exam Utility

- Retrieval-optimized
- Quick revision genuinely quick
- No decorative fluff

### H. HOTS

- Present where applicable
- Absent where not
- Genuinely higher-order

### I. Step-trace & Final Answer

- Trace/output questions use Step-trace format
- Trace answers close with a Final Answer line
- Final Answer is one line, not a paragraph

### J. Safety

- No exam predictions
- No future question claims
- Past papers framed as historical evidence

### K. Style Consistency (if render-style applied)

- Heading levels consistent
- Source tags right-aligned or inline consistently
- Code blocks use same border/label style
- OUTPUT/TRACE blocks visually distinct from code
- Callouts (Exam relevance, Gotcha, Note) styled consistently
- Table headers uniform
- Page breaks before each Unit, Quick Revision Sheet, and Index

## Repair Loop

1. Identify affected sections
2. Regenerate or patch
3. Re-run affected checks
4. Re-run full checklist if repair touched >20% of pack

Max 3 iterations. Report if still failing.

## Output

Status: PASS or FAIL with itemized results.
